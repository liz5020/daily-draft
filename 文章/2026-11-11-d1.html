約 4 分鐘　深讀　AI 協作與治理　昨天新增

全職媽媽想用 Claude Code 剪片，差點對網紅外掛一路按「允許」

一位剛開始研究 AI 的全職媽媽，想用 Claude Code 搭配網紅提供的外掛來剪片，先請工程師老公幫忙裝 Git，卻換來一句嚴肅的「還好妳有先問我」。這篇貼文把她被教的十五分鐘整理成大家都能用的提醒：外掛等於別人寫的程式，而 AI 在你的電腦上可以讀、改、刪檔案，一路按「允許」很危險。留言區還補上了更正與一堆實用做法，值得細讀。

事情經過

作者自述是全職媽媽，終於要來研究 AI。她看到教學說，要先在電腦上安裝 Git，才能在 Claude Code 裡順利使用網紅提供的外掛（plug-in）來剪片，於是問工程師老公能不能幫忙。老公馬上變臉，很嚴肅地說「還好妳有先問我」，教了她十五分鐘，她才發現這件事給出去的權限非常高，自己差點盲目授權。

真正危險的是什麼

  • 不是 Git 本身。Git 只是一個工具，問題不在它。
  • 外掛＝別人寫的程式。你不知道裡面寫了什麼，卻要在自己的電腦上執行它。
  • AI 有很大的動作空間。它在你的電腦上可以讀檔、改檔、刪檔；如果對每個跳出來的視窗都不加思考地按「允許」，等於把這些權限整包交出去。

老公的做法：裝沙盒

老公的方案是裝沙盒（用 Docker 這類工具），概念是用技術隔出一個「極小型的獨立安全房間」：萬一出事，只燒到房間，不會燒到整棟房子，才不容易發生無法挽回的毀滅性後果。作者自己也強調：沙盒是大幅降低風險，不是零風險。

最高讚的更正：Docker 不等於沙盒

留言中最多人按讚的一則指出：Docker 不是真正的沙盒，它和主機共用同一個 Linux 核心，有機會發生「沙盒逃逸」。另有幾位網友說，想要真正隔離就該架虛擬機（VM）。作者的回應很誠實：原本以為有沙盒就安全，現在才知道還要看權限怎麼設；沒有工程背景的人最難的，是不知道自己到底開放了什麼權限。一般的說法也是：容器隔離弱於虛擬機，設定錯誤（例如給特權模式）還會擴大風險。

網友提供的做法

一、先別直接用別人的外掛

  • 賣外掛的人多半是拿免費開源的來改，可以請 AI 研究那個功能後自己做一份，或借鏡有哪些功能值得做。
  • 也可以把外掛丟給 AI，先掃描風險、列出會用到哪些權限。作者追問：自己做的還是要在電腦上跑，不懂程式的人怎麼確認安全？這一點留言沒有一致答案。

二、裝之前先問三句，並隔離環境

  1. 這是誰寫的？
  2. 它要讀、改哪些資料夾？
  3. 能不能只開一個素材資料夾給它？

另外，剪片用的帳號與信箱和平常分開，重要檔案先備份。

三、連同設備一起分開

  • 給 AI 用的 email、信用卡、甚至電腦都另外準備一套。
  • 沙盒裡不要放 API 金鑰、登入中的帳號與付款資料。

四、少裝一點

  • 有人說 Claude 已經強到不需要外掛，也有人說該給的是 skill 而不是 plugin。
  • 也有人認為 GitHub 上的東西別亂裝，裝多了忘記，還浪費 token。作者回說，新手連哪些 skill 需要、哪些有風險都沒有判斷力，只會當一般 App 在裝。

留言裡的分歧

有人說 Docker 隔離是「最起碼」要有的；也有人說 Docker 不等於安全，要用 hook 限制或 VM 才對；還有人說最簡單的辦法就是別用。

三種意見其實不衝突，差別在你願意花多少力氣換多少安全。

新手最容易卡住的地方

作者的幾則回覆點出了真正的難處：新手連哪些 skill 需要、哪些有資安風險都沒有判斷力，只會把它當成一般 App 來裝；很多 AI 課程也只會請你直接裝；她自己能先問到人，是因為家裡剛好有工程師。這提醒我們，風險不在「不夠聰明」，而在「不知道自己開放了什麼」。

按下「允許」之前，可以問自己的四件事

  1. 這個外掛或指令是誰寫的？我找得到來源嗎？
  2. 它要讀、改、刪的是哪些資料夾？
  3. 能不能只給它一個專用的素材資料夾？
  4. 如果它出錯，我有備份、有獨立的帳號可以收拾嗎？

這四題是把網友的建議濃縮成一張檢查表。一般的說法是：權限越小、環境越隔離，出事的代價就越小；但沒有一種做法能保證零風險，所以多一層保護，就多一分餘裕。

可以怎麼用

今天就做一件事：回頭看看你電腦上裝過的外掛或 skill，挑一個你說不出來歷的，請 AI「只讀、不執行」幫你列出它會碰哪些資料夾與指令（見下方給 AI 的指令）；下一次跳出「允許」時，先花五秒鐘看它要的是什麼權限，再決定按不按。

來源與備註：Threads 帳號 @smallhandcook（美食與生活類帳號），約 2026-11-09 發文，內容為作者自述的個人經歷；沙盒與 Docker 的技術說明有資料支持，網紅外掛的具體內容作者沒有說明，部分數字未查到出處。

給 Claude Code 的指令

適合情境：你想裝別人做的外掛或 skill，但不確定安不安全時

請先讀懂下面的需求，列出你打算讀哪些檔案、改哪些地方、步驟是什麼，等我說「好」再動手；不要直接修改或刪除任何檔案。

請先讀懂下面的需求，列出你打算讀哪些檔案、步驟是什麼，等我說「好」再動手；全程只讀取，不要執行、修改或刪除任何檔案。

我想安裝一個第三方外掛／skill，資料夾在【貼上路徑】。請幫我做三件事：
1. 列出它的所有檔案，找出會讀寫哪些資料夾、會不會連網、會不會執行系統指令。
2. 找出可疑的地方（例如讀取密碼檔、把資料傳到外部網址、刪除檔案），逐項說明原因。
3. 用白話告訴我：如果要安裝，最小需要開放哪些權限，建議放在哪個專用資料夾。
最後給我一個結論：建議安裝、小心安裝或不要安裝，並說明理由。

貼進 Claude Code 後，它會先列出要改什麼、等你說「好」才動手。同一份指令也存在原筆記的「給 AI 的指令」。
