約 1 分鐘　頭條　AI 協作與治理　昨天新增

對話壓縮的代價，與換新對話前寫交接檔的做法

Claude Code 這類工具在對話快滿時，會自動把前面整段對話讀一次、寫成摘要，再用摘要開新對話接著做，而且不會先問你。Threads 上的 @quiet_resting 介紹這件事的代價，並分享自己的替代做法：在換新對話之前，先請 Agent 寫一份交接檔。

壓縮的代價

作者轉述 Alexander Yue（@Alezander9，2026-10 的 X 長文，第一句是「壓縮對話是個錯誤」）的量測：一段約 40 萬 token 的真實工作，壓縮一次，快取過期時要 38 秒、1.99 美元；快取還在時 29 秒、0.17 美元。他更在意的是摘要會丟重要訊息：「精確的錯誤訊息、檔案路徑、你需要的那一個數字，常常不見了。」

他的做法是把每段對話完整存成檔案，塞滿就開新對話，要用時叫它回去搜舊紀錄、抄需要的幾行，同一段工作 15 秒、0.10 美元。有人問寫交接檔行不行，他說交接本身也是一種壓縮。（這些是他自己的量測，而他也是相關工具的作者，立場要留意。）

作者的交接檔做法

不等自動壓縮，一件大事做完、或 Agent 提醒快滿了，就先寫交接檔再開新對話；新對話只讀這份，回「已接手」。交接檔固定五段：下一段先做什麼、做到哪、做了哪些決定和為什麼、試過但行不通的、要讀哪些檔。

其中最不能空白的是「試過但行不通的」：摘要最常丟掉它，少了它，新對話會重走一遍死胡同。

可以怎麼用

下次一個長任務告一段落時，不要繼續塞同一段對話，先請 AI 照這五段寫交接檔，再開新對話只貼這份。

來源與備註：@quiet_resting，Threads，2026-11-10；轉述 Alexander Yue 2026-10 的 X 長文並加上自己的做法。

給 Claude Code 的指令

適合情境：一個長任務做到一半、對話快滿或想開新對話時

請先讀懂下面的需求，列出你打算讀哪些檔案、改哪些地方、步驟是什麼，等我說「好」再動手；不要直接修改或刪除任何檔案。

這段對話我想先收尾再開新對話。請幫我寫一份交接檔，存成專案資料夾裡的 交接檔.md，固定這五段：
1. 下一段先做什麼
2. 目前做到哪
3. 做了哪些決定，以及為什麼
4. 試過但行不通的（要寫清楚做了什麼、為什麼不行，這段不能空白）
5. 要讀哪些檔案（列出完整路徑）
寫完後請把內容貼給我確認。之後新的對話我會只讀這份檔案，請寫到讓新對話不用回頭看舊紀錄也能接手。

貼進 Claude Code 後，它會先列出要改什麼、等你說「好」才動手。同一份指令也存在原筆記的「給 AI 的指令」。
