約 3 分鐘　深讀　AI 協作與治理　舊文 11/17

換新模型前一定先丟的 4 個 prompt：不看跑分，用自己的工作測

每次有新模型推出，社群上都是「評測創新高」的消息。有位一人 AI 公司的經營者，自述不會寫程式，看不懂跑分圖，所以每次都丟同一套四個 prompt 進去試。他的第一反應不是「快換」，而是問自己：我憑什麼知道它對我比較好？這套做法很土，但每一步都可以直接照著做。

起點：看不懂跑分，就用自己的工作測

作者提到，Anthropic 推出新一代 Claude，官方說評測分數創新高。對工程師來說，跑分圖可以拿來參考；對他這種每天在做 dashboard、自動發文、日常營運的人來說，分數幫不上忙。他的原則是一句話：把我真的在做的事丟給它，看它做不做得完。分數再高，我的 dashboard 做不出來，就是沒用。

① 翻舊帳：同一題重做一次

貼上之前給 AI 的任務，和當時它給的回答，請它同一題現在重做，並且直接告訴你哪裡比上次好、哪裡變差。這一招的好處是有基準：你已經知道舊答案哪裡不滿意，新模型有沒有改善，一眼就能看出來。

留言裡有讀者提醒一個小坑：如果你告訴它哪一份是舊答案，它會順著你的期待去改，比較就不準了。想比得準，最好做成盲測，不要說明哪一份是舊的。

② 考我的事：挑一件從頭做完

先列出你每天在做的 5 件事，然後請它挑一件，從頭做到尾，中途不要問你問題，做完再告訴你卡在哪。這是在測「能不能獨立交付」。很多模型單題回答很漂亮，但碰到要自己補資訊、自己做判斷的完整任務，才看得出差別。作者要的不是答案多漂亮，而是它有沒有能力把一件事做完。

③ 問它極限：它什麼時候會出錯

問它：這個任務你做到什麼程度會開始出錯？請講 3 個你會失手的狀況，還有我該怎麼寫 prompt 來避開。留言讀者認為這是四招裡最實用的一招：大多數人只測 AI 會什麼，不測它什麼時候翻車，但真正要拿來工作，翻車的邊界比能力上限更重要。

這一招的另一個好處是，它同時給你一份「怎麼寫 prompt 避開」的使用說明，等於測試與學習一起完成。

④ 留退路：把做法寫成可以搬走的文件

最後請它把剛才這套做法寫成一份文件，讓你換到別的 AI，也能貼進去照跑。這是在避免被單一工具綁住：你的流程寫在自己手上，而不是只存在某個模型的對話紀錄裡。換工具的成本因此變低，下次有更新的模型，也能用同一份文件再測一次。

留言補的一關：連跑三次

同一位讀者還建議，再加一關：同一題連跑三次。很多模型第一次答得漂亮，第二、三次品質就飄掉，而真正出貨最怕的就是不穩定。這個補充和作者的方法互補：四招測的是能力與邊界，連跑三次測的是穩定度。讀者最後也好奇，跑完這幾關，作者目前比較推薦哪一個版本，貼文裡沒有明確回答。

這套方法的限制

做法好處要注意
翻舊帳有基準可比最好盲測，別透露哪份是舊的
考我的事測獨立完成度一次只代表一件事
問它極限知道何時會翻車模型自述不一定準，要用實際任務印證
留退路降低被綁定文件要定期更新

這是個人的實測方法，沒有對照實驗，樣本也只有作者自己的工作內容。它不是在比哪個模型客觀上最強，而是在回答「對我的工作有沒有比較好」。這個問題很個人，也因此很實用。

可以怎麼用

下次有新模型，先不要急著看評論。挑一件你上週真的做過的事，把當時的任務與回答貼給新模型，請它重做並比較；再問它三個會失手的狀況；最後請它把這次的做法存成文件。三十分鐘內，你就會有一份屬於自己的「換不換」判斷。

來源與備註：貼文來自 @eibon9527（自述經營一人 AI 公司、不寫程式），2026-11-16 發在 Threads，為個人實測分享，非專業意見，沒有對照實驗。貼文提到的部分新模型名稱細節，我沒有找到可對照的資料。四個 prompt 可直接使用，建議先小範圍試用。

給 Claude Code 的指令

適合情境：新模型推出、你想知道它對自己的工作有沒有比較好時

請先讀懂下面的需求，列出你打算讀哪些檔案、改哪些地方、步驟是什麼，等我說「好」再動手；不要直接修改或刪除任何檔案。

我想測試新模型對我的工作有沒有比較好。請依序做：
1. 我會貼上之前給你的一個任務與當時的回答，你同一題重做，並直接說哪裡比上次好、哪裡變差。
2. 我會列出我每天做的 5 件事，你挑一件從頭做完，中途不要問我問題，做完告訴我卡在哪。
3. 告訴我這個任務你做到什麼程度會開始出錯，講 3 個會失手的狀況，以及 prompt 怎麼寫可以避開。
4. 把這套做法寫成一份文件，讓我換到別的 AI 也能貼進去照跑。
請先等我貼上第 1 步的內容再開始。

貼進 Claude Code 後，它會先列出要改什麼、等你說「好」才動手。同一份指令也存在原筆記的「給 AI 的指令」。
