數據分析師工作上 SQL 要學到什麼程度

@yzkijhuo_ 目前靠 GPT 學 SQL，覺得有點太基礎，想問工作上到底要學到什麼程度。串裡最有內容的回答是：語法不難，難的是業務與資料。其他留言補了幾個很實際的角度，也有人唱反調。

最完整的回答：六項語法

@autumn.__.0426 說，工作上的 SQL 語法大致就是下面六項，並且先強調：真正難的是所屬產業或公司的業務邏輯、領域知識，以及判斷彙整出來的數據合不合理。

  1. SELECT 等基本查詢（DML）。
  2. CREATE、ALTER 等建表與改表（DDL），順便了解索引（INDEX）的概念。
  3. GROUP BY 分組與彙整函式（MAX、AVG 等）。
  4. 各類型的 JOIN，「非常常用」。
  5. UNION 與 UNION ALL，「非常常用」。
  6. 視窗與分析函數（partition by … order by），整理資料、做報表常用。

學習路線：先用歐萊禮的《SQL 學習手冊》建立系統化的知識地圖；基礎熟了之後，再往「效能與最佳化」走，學什麼樣的 SQL 才是高效率的。

其他人的補充：難在資料，不在語法

  • 進公司後最難的是「亂到不行的表格跟欄位」。
  • 要能在腦中想像資料表的結構與關聯（一對多、多對多），並預判不同查詢會怎麼改變資料的維度與粒度。
  • 不同公司的資料性質落差很大，要靠對資料的敏感度，所以「SQL 很吃經驗，很難獨立學」。
  • 有人被塞了一堆髒數據，是先搞懂窗口函數才撐過去。

該練什麼

  • 各類型 JOIN 與優化。
  • 刷 LeetCode 練窗口函數；寫的時候每改一點就把輸出貼到 Excel 看，幫助理解資料結構，也容易抓出不是語法的定義錯誤。
  • 自動回覆的 @meta.ai 給的檢核線：必熟 JOIN 全類型、GROUP BY／HAVING、CASE WHEN、CTE、Window Function（ROW_NUMBER、RANK、LAG／LEAD）；加分是效能意識（EXISTS 對 IN、索引）與髒數據處理（NULL、去重）。作者回說跟 GPT 講的差不多。

兩種反方意見

  • 「現在直接叫 AI Agent 查就好，語法都不需要會。」
  • 「所有 SQL 都服務業務，連業務都搞不懂時學 SQL 沒意義。」

一題現成的練習題

有員工表與月薪表，每位員工同一個月可能有多筆薪資（扣款為負數）。請：①統計 2026 年 10 月每人的當月收入；②所有人都要列出，沒有當月紀錄的顯示 0；③由高到低排序。提示（我的補充）：先想要用哪種 JOIN 才不會漏掉沒紀錄的人，再想怎麼把 NULL 變成 0。

跟知識庫怎麼接

這跟學習整理裡的「直接練習、攻擊自己的弱點」同方向：語法學完，要拿真實問題練；也跟「先知道夠用是什麼，才知道還缺什麼」相通。至於「叫 AI 查就好」，知識庫的 AI 使用整理有一條相關的提醒：AI 交回成果後要自己驗收，而「判斷數據合不合理」正是這裡的業務邏輯，AI 替你寫語法，仍然需要有人看得出結果對不對。

可以怎麼用

用手上真實的資料表，寫一個會用到 JOIN 的小問題，每改一次就把輸出貼出來對照，不要只看有沒有報錯。
