Opus 帶一群 Haiku 分工，成本省一半：85 頁文件檢查的對比測試

有人在 Threads 問：Haiku 到底能做到多複雜的工作？他自己的組合是 Fable 規劃、Opus 分派與審核、Sonnet 開發，從沒想過放 Haiku。底下他轉述了一篇 Reddit 測試：讓 Opus 當指揮、派一群 Haiku 分頭做大範圍檢查，品質比 Opus 單打高，成本約砍半。但這個結論有條件：任務一小，結果就反過來。

測試怎麼做的

測試者用開源專案 buildbot（約 10 萬行程式碼）當題目，貼文說跑了快 300 組對比，不過多數組合只跑 2 次，測試者自己在表上寫「只能當強烈暗示」。成本用的是 API 公開價格，拿來估訂閱方案的用量。比較的組合有：Opus 單獨（不准分派）、Opus 自由發揮（可以分派但從來沒分派過）、Opus 加 Sonnet（用一個 Skill 決定派誰）、Opus 加 Haiku，後來又補跑了 Haiku 單獨與 Sonnet 單獨。

讀大量內容：Opus 加 Haiku 最划算

三項閱讀任務（替約 400 個程式檔寫摘要，加兩份文件檢查）合計：Opus 單獨約 $8.98，Opus 加 Haiku 約 $4.44，便宜 51%，兩頁文件檢查的成績也更好（Opus 單獨合計找到 22 個，Opus 加 Haiku 找到 28 個）。摘要部分每組都涵蓋了全部 400 個檔案，彼此看不出明顯差距。

最大的一項是「讀 85 頁文件，找出文件與程式不符的地方」，清單上共有 92 個真錯誤。每組跑兩次，結果如下：

  • Opus 單獨：兩次各找到 36、38 個，合計 49 個不同的錯誤，約 $4.11。
  • Opus 加 Haiku：58、63 個，合計 72 個，約 $1.93，便宜 53%。
  • Opus 加 Sonnet（用 Skill 分派）：55、70 個，合計 77 個，$3.88，只便宜 5%。
  • Haiku 單獨：42、41 個，合計 54 個，$1.93，便宜 53%，但要花約 12 分鐘，是組合裡最慢的。
  • Sonnet 單獨：39、64 個，合計 67 個，$3.21，便宜 22%。

「合計」指兩次跑出來的不同錯誤加在一起。看起來最亮眼的是 Opus 加 Haiku：找到的錯誤比 Opus 單獨多將近一半，錢卻只花一半。

寫程式：便宜很多，但有一個洞

第二張表是兩個比較難的寫程式任務：加一個 REST 端點，以及找一個離症狀很遠的 bug。Opus 加 Haiku 便宜 30%（$1.36），品質沒有掉；Haiku 單獨便宜 93%（$0.15），官方測試過了，但速度優化沒做，也沒有發現「這個症狀怪怪的」，兩項都是 0／2。Sonnet 單獨便宜 71%，測試全過，同樣沒有抓到奇怪的症狀。也就是說，測試分數看不出來的「判斷力」，在便宜模型單打時掉了。

作者補充的結論

重點不是 Haiku 比較強，而是 Opus 帶著一群 Haiku 並行，讀的量約 3 倍、寫的量約 8 倍，總價反而砍半。他還點出一件事：Opus 自己放著不管，從來不會主動分工，所以分工要靠你設計。小任務則反過來：Opus 單獨做更便宜、更準，因為分工本身的額外開銷會吃掉價差。他整理的口訣是：大範圍檢查、文件審查，用 Opus 加 Haiku；小任務、定義清楚的，Haiku 單獨上。

預估與實際的落差

測試者還做了一件誠實的事：把事前預估的省錢幅度和實際結果並排。Opus 加 Haiku 預估省 82 到 88%，實際省 46 到 53%；用 Skill 分派的組合，預估省 32 到 39%，實際從便宜 5% 到貴 32% 都有。所以拿預估數字去規劃預算，要打折。

留言怎麼說

  • 有人問：Haiku 找到的真的是真錯誤嗎？（表上說，答案清單由 Opus 對照程式逐一確認。）
  • 有人認為 Haiku 適合重複性大的資訊苦工，要它算複雜的東西就會歪。
  • 有人覺得：Opus 自己查 49 個，加 Haiku 變 72 個，換一雙眼睛檢查，比同一個模型自己回頭看有用。
  • 有人的做法是先讓 Haiku 做格式檢查與抽欄位，需要判斷的再交給大模型，重跑也不心疼。

讀的時候要留意

  • 這是轉述別人的測試，不是作者自己的實驗；多數組合只跑 2 次，樣本小。
  • 答案清單是 Opus 對照程式確認的，所以不包含「每次都沒人找到」的錯誤，92 不是文件裡錯誤的總數。
  • 圖上署名的 GitHub 專案我搜尋沒有找到，Reddit 原帖也沒能打開，所以只能核對貼文與圖上的數字是否對得上，它們是對得上的。
  • 成本是 API 公開價，不等於你的訂閱額度；也要把時間算進去。

可以怎麼用

挑一件「量大、判斷不難」的事試一次，例如請 Opus 帶幾個 Haiku，把一個資料夾裡 30 份文件逐份對照最新規格，列出不一致的地方；同時自己抽三項回頭核對是不是真的錯誤。如果只是改一兩行的小事，就別分工，直接做。
