約 2 分鐘　頭條　AI 協作與治理　昨天新增

Claude Academy 29 門課反覆出現的 4 組概念

Claude Academy 的課很多，容易學得很散。@yojuhsu 把 29 門課反覆出現的概念歸成 4 組，並標出每個概念在幾門課出現。他特別說明：這張關係圖是他自己的整理，不是 Anthropic 的官方架構。

第一組：和 AI 協作（4D 框架）

4D 是四個動作的循環：委派（決定哪些事交給 AI）→ 描述（把要的成果說清楚）⇄ 辨別（確認有沒有做對）→ 審慎（為成果負責），審慎之後再回到委派。描述和辨別是會來回的一圈：說清楚、看結果、再補說。課程頁寫的目標是「有效、高效、合乎道德且安全地與 AI 協作」。

第二組：Claude Code 客製化

  • CLAUDE.md 對 Hooks：CLAUDE.md 是「建議」，Hooks 是「強制」。一定要遵守的事用 Hooks 擋住；CLAUDE.md 寫太長，AI 遵守的程度會下降（各在 3 門課出現）。
  • Subagents 對 Context 管理：輸出很多的旁支工作交給 Subagent，只把摘要帶回主對話，主對話的空間才留得住（Subagents 在 3 門課、Context 管理在 2 門課出現）。

第三組：工具與連接

工具分兩種：客戶端工具由你的程式執行、伺服器端工具由 Anthropic 執行，簡單的分法是「看誰按下執行鍵」（各 3 門課）。MCP 是工具的來源之一，接進客戶端使用（4 門課）；連接器（Connectors）是日常會用到的那一層，可以連到任何支援 MCP 的服務（2 門課）。

第四組：Skills 與 CLAUDE.md

CLAUDE.md 放「每次都要知道」的事（3 門課）；Skills 放「詳細流程，用到才載入」（5 門課）。作者提醒，Skills 這同一個概念在 5 門課裡長得不一樣，所以他另外做了地圖頁，點概念就能看它出現在哪些課的哪個單元。

跟你的知識庫怎麼接

  • 「CLAUDE.md 要短、強制的交給 Hook」就是第二組；「規則放每次都要的、流程做成 skill」就是第四組。知識庫的 AI 規則整理把這些放在同一條線上，先看地圖，再決定每件事放哪裡。
  • 把 4D 對回平常用法：「描述」就是下指令時先講清楚規格，「辨別」就是拿到成果後檢查驗收（這是整理知識庫時的對照，不是原文說法）。
  • Subagent 與 Context 的做法，可以接到今天另一篇「Agent 的 8 種浪費」：旁支工作分出去，主對話才不會被撐爆。

可以怎麼用

選課時別從第一門開始，先問自己現在卡在哪一組：總是講不清楚就先看 4D；設定越寫越長就看第二組；流程一直重複就看 Skills。這期有附一則指令，可以請 Claude Code 幫你檢查設定有沒有放對地方。

來源與備註：Threads @yojuhsu，2026-11-12，5 張關係圖。圖是作者的個人整理；課程免費，部分實作需要付費的 Claude 方案或 API 金鑰。4D 框架確實是 Anthropic 的 AI Fluency 框架，對應約 3 小時的入門課；「共 29 門課」與各概念「N 門課出現」是作者自己數的，沒找到獨立來源。

給 Claude Code 的指令

適合情境：想知道自己的 Claude Code 設定有沒有用對地方（CLAUDE.md、Hooks、Skills、Subagents）時

請先讀懂下面的需求，列出你打算讀哪些檔案、改哪些地方、步驟是什麼，等我說「好」再動手；不要直接修改或刪除任何檔案。

請幫我檢查我目前專案的 Claude Code 設定放對地方了沒有。步驟：1. 讀我的 CLAUDE.md、.claude 資料夾（hooks、skills、agents 若有）和設定檔，沒有的就說沒有。2. 用這個原則分類：每次都要知道的放 CLAUDE.md（要精簡）；一定要強制遵守的做成 Hooks；詳細流程、用到才載入的做成 Skills；輸出很多的旁支工作交給 Subagent，只把摘要帶回主對話。3. 列出現在放錯地方或太長的內容，各說一句白話理由，並建議該搬去哪裡。4. 最後只給我一個最值得先改的建議。先只列報告，不要動任何檔案。

貼進 Claude Code 後，它會先列出要改什麼、等你說「好」才動手。同一份指令也存在原筆記的「給 AI 的指令」。
