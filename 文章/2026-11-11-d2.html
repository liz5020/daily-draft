AI 治理框架 OAC：可觀測、可授權、可停止

當 AI 開始替人做決定，最危險的可能不是它犯錯，而是犯錯時沒有人知道怎麼讓它停下來。研究者 EliyahOren 把這個問題整理成三層框架：可觀測、可授權、可停止。它原本談的是企業裡的多 AI Agent 系統，但縮小到你我自己用 AI 的情境，同樣能拿來檢查：它碰得到什麼、做了什麼看得到嗎、要停時停得下來嗎？

先看一個情境

文章用一個假設的場景開頭：凌晨 2:17，一家企業的 AI Agent 正在自動處理跨部門任務，它可以讀取文件、呼叫 API、修改資料庫，甚至指揮其他 AI Agent。突然系統收到一項與原任務衝突的指令：

  • 第一個 Agent 認為應該繼續；
  • 第二個 Agent 判斷有風險；
  • 第三個 Agent 提出新的執行方案。

三個 AI 都有自己的理由，真正的問題是：誰有權說「停止」？這是假設情境，卻點出一個值得研究的治理問題。

為什麼現在才問這個

過去 AI 是工具，工具出錯，人類停止使用就好。但當 AI 逐漸具備長期記憶、工具呼叫、任務規劃與多 Agent 協作的能力，問題就不再只是「模型答得對不對」，而是整個系統是否仍然可控。

OAC 三層

① Observability 可觀測

系統必須能回答四件事：

  • AI 收到什麼指令？
  • 做出了哪些決策？
  • 呼叫了哪些工具？
  • 留下了哪些可供稽核的證據？

如果連發生什麼事都無法重建，就很難建立責任機制。

② Authority 授權邊界

AI 可以提出建議，不代表它擁有無限制的執行權。要先想清楚：

  • 哪些操作可以自主完成？
  • 哪些必須經過人類批准？
  • 哪些權限應該隨時可以撤銷？

重點是：授權不應只存在於提示詞裡，而要落實在可執行的系統控制中。

③ Containment 限制與停止

出現異常時，系統能不能停止高風險操作、撤銷權限、隔離受影響的元件，並保留調查紀錄？這一層是最後的安全網。

哪些是已知的、哪些還在研究

類別內容
已知的工程原則日誌、最小權限、權限撤銷與隔離，本來就是資訊系統安全治理的重要手段
研究中如何把這些控制整合到長期運作的多 AI Agent 系統，並證明有效
前瞻假說未來 AI 系統的競爭力，可能不只看自主能力，也看能否接受外部監督、修正與停止

作者自己說得很清楚：OAC 不是已完成驗證的產品，而是供後續工程實驗與治理設計用的分析框架。

給企業的提問

不要只問 AI 能替我們完成多少工作，還要問：當 AI 不應該繼續工作時，我們能否確實阻止它？

文章的結論是：值得信任的自主系統，不是永遠不犯錯，而是錯誤發生時仍保有可追溯、可治理、可控制的邊界。

縮小到個人使用

你不需要有企業系統，也能套用這三層：

  1. 可觀測：AI 做過的事我看得到紀錄嗎？（例如對話與操作歷史、檔案的修改紀錄）
  2. 授權：我給它的存取範圍有多大？有沒有哪些動作應該改成「每次都問我」？
  3. 停止：它做到一半我要怎麼讓它停？停了之後能不能還原？

三層怎麼一起運作

回到凌晨 2:17 的情境：三個 Agent 意見不同、沒人能說「停」，其實是三層同時缺席。沒有可觀測，就看不到誰下了什麼指令、為什麼衝突；沒有授權邊界，就不知道誰有權決定繼續或暫停；沒有停止機制，即使知道出事了也收不回來。所以三層是疊在一起的：先看得見，才談得上管；先管得住，出事時才有底線。

這個框架的定位

要特別留意：這不是已經證明有效的標準，作者把證據分成三類（已知的工程原則、研究中的整合方式、前瞻的假說），並明說自己的框架是後續實驗與治理設計用的起點。貼文也帶有作者團隊介紹研究方向的性質，且情境是假設的。把它當成一張好用的檢查表，而不是結論，會比較貼近原意。

可以怎麼用

今天花十分鐘，打開你最常用的 AI 工具的權限設定，只問自己這三個問題各一次；如果有哪一題答不出來，就是你該補的缺口。也可以直接把下面的指令交給 Claude Code，請它只讀、不改，幫你盤點。

給 Claude Code 的指令

適合情境：你想檢查自己給 AI 的權限開得太大、或出事時停不停得下來時

請先讀懂下面的需求，列出你打算讀哪些檔案、改哪些地方、步驟是什麼，等我說「好」再動手；不要直接修改或刪除任何檔案。

請用「可觀測、可授權、可停止」三個角度，幫我盤點目前這台電腦上 Claude Code 的使用狀況。全程只讀取，不要修改、刪除任何檔案或設定。

步驟：
1. 讀取我的 Claude Code 設定檔（settings.json 與 settings.local.json，若有）與 CLAUDE.md，列出目前允許自動執行的指令、能讀寫的資料夾、有哪些 hook。
2. 可觀測：說明我現在能在哪裡看到你做過的操作與檔案修改（例如對話紀錄、版本紀錄），哪些地方看不到。
3. 可授權：指出哪些權限開得比必要的更大，建議改成「每次詢問」的項目。
4. 可停止：說明我在你執行到一半時可以怎麼中斷，以及如何還原被你改過的檔案。
最後用白話給我三個最優先要補的缺口，每個附一個具體的設定建議，但先不要動手改。

貼進 Claude Code 後，它會先列出要改什麼、等你說「好」才動手。同一份指令也存在原筆記的「給 AI 的指令」。
