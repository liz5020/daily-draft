Thorsten Ball：和 AI agent 共事的十五條做法，最大的改變是「要證據」

Thorsten Ball（自述在 Amp 工作的工程師）把平常私訊給朋友的做法整理成一篇短文，標明「截至 2026 年 10 月」。他列了十五條，核心想法只有一個：模型已經夠強，瓶頸變成「你怎麼讓它做事、怎麼確認它做對」。值得看的原因是，這些條目都是日常可以直接改的習慣，而且他明說其中一條是「最大的改變」。

一、模型與提示：用最強的，描述「要什麼」

用最新最強的模型，其他選擇都可能是浪費時間。他的理由是：模型錯 10% 但你不知道是哪 10%，結果就是反覆重試。他的比喻是，你會想請一個便宜 50%、卻隨機笨 20% 的通才嗎？

別再擔心程式碼變成垃圾堆。「會讓程式碼庫變得無法維護」這句話，也許半年前是真的；現在他不確定它真的製造垃圾，就算有，也不確定結果就不能維護。

描述「要什麼」，不是「怎麼做」。例如「讓編譯器與 VM 盡可能快，沒快兩倍不要停」，或是直接描述最後應該長什麼樣子，往往比一步步指揮得到更好的結果。

二、讓整個開發流程對 agent「看得見」

  • 看不見的東西它會編。是什麼讓幻覺減少？是工具呼叫，它讓 agent 碰到真實世界。所以讓它能實際跑出自己做的東西、讀正式環境的 log、部署、看發版、切版本、開關功能旗標、處理 bug 回報並寄信給使用者。「你看得到的，agent 也該看得到。」
  • 替這些流程做工具。他們有自製外掛處理 bug 回報、寄信給使用者、回答「系統健康嗎？」、開功能旗標。
  • 測試「知識」有沒有被用到。AGENTS.md、skills、腳本、文件裡堆了很多知識，但 agent 真的會用嗎？叫五個互不知情的 agent 做對照組與實驗組比一比，agent 很會跑實驗。
  • 本機開發變得不舒服。每個 agent 都該能自己安裝、執行需要的東西；遠端機器容易，本機則很難避免資源衝突。

三、驗證與迭代：別一輪一輪試，要證據

不要和 agent 一輪一輪地試，請它做工具來試。不是「試這個……啊不對，試那個」，而是「產生 20 種變化，加一個頁面讓我組合測試」。問題端也一樣：「給我 4 個為什麼慢的假設，然後全部驗證。」

要求無可反駁的證據（他說是最大的改變）。agent 很會產生證據：端到端演示、示範影片、前後數字。你要慢慢建立信任與直覺，並在 AGENTS.md 寫上「這不是證據」，擋掉「看起來應該可以」的說法。

四、時間與記憶：別等 agent，讓它們等你

  • 擔心首字延遲，多半是用法不對；多用非同步，給更大的任務、更有野心，一次批次交代而不是來回問。
  • 排程、喚醒、heartbeat 是殺手功能。例：「兩小時後查 log」「上線後通知我」「每天九點檢查」。他說關掉後才發現非常想念。
  • 不手動管理 context。在意用了 30 萬還是 38 萬 token 是浪費心力，壓縮很好用；一個討論串一個任務（有的 46 則訊息，有的 3,714 則）。
  • 討論串是公司的記憶。在 Amp 裡討論串連到 git commit，能回頭問「當初為什麼這樣做」，也避免重工。

五、人的角色：少寫、少審，但要抓對地方

不要讓 agent 替人寫東西，例外是除錯步驟、事故報告、部分文件這類機械性內容。只審查「爆炸半徑大」的程式：少於 5 個核心檔案、資料庫遷移。用 closure 還是 class、型別整不整齊、變數命名、甚至重複，他都不在乎。他只問四件事：

  1. 能跑嗎？
  2. 我看得懂「箭頭圖」的層級嗎？
  3. agent 端到端測過嗎？
  4. 一個月後我改得動嗎？

四個都是「是」，才可能去看程式碼。

他明說這是個人經驗、會隨時間過時，沒有附數據；「Opus 4.5 已過時」這類說法只是一時的看法。

可以怎麼用

今天只做一件事：打開你的 AGENTS.md 或 CLAUDE.md，加一行「完成時要附證據（實際執行結果、前後數字或截圖），『應該可以』不算證據」，下次交付任務時看 agent 怎麼回你。

給 Claude Code 的指令

適合情境：你想讓 AI 交付的東西更可靠、少聽到『應該可以』時

請先讀懂下面的需求，列出你打算讀哪些檔案、改哪些地方、步驟是什麼，等我說「好」再動手；不要直接修改或刪除任何檔案。

請幫我檢查並更新這個專案的 CLAUDE.md（或 AGENTS.md）：
1. 先讀目前內容，不要刪掉原有規則。
2. 新增一段「完成標準」：每次說任務完成時，必須附上證據，包括實際執行的指令與輸出、前後數字對照，或端到端跑過一次的結果；只說「應該可以」「看起來沒問題」都不算證據。
3. 再加一條：遇到要比較多種做法時，不要一輪一輪問我，先做出可以並排測試的小工具或腳本，再讓我選。
4. 改完後把新增的內容貼給我確認，不要自行做其他更動。

貼進 Claude Code 後，它會先列出要改什麼、等你說「好」才動手。同一份指令也存在原筆記的「給 AI 的指令」。
