使用 Agent 最常見的 8 大浪費 Token 行為

AI 用量高，不代表效率好。真正有效率的 Agent，不是 Token 用得越少越好，而是用合理的資源完成高品質的工作。下面八種行為最常讓 Token 白白燒掉，每一種都有「錯誤案例」和「節省策略」。

八個陷阱

1. 需求模糊

只說「幫我做一份精美簡報」，Agent 做了 40 頁才發現你只需要 20 頁，整份重來。做法：先指定受眾、頁數、格式、限制與驗收標準，再請它確認大綱。口訣：先定規格，再動工。

2. 上下文過度膨脹

只想改首頁的一顆按鈕，Agent 卻先把數百個無關檔案讀進來。做法：先看專案目錄、定位相關元件、需要時才讀檔。口訣：精準載入，不是全部塞入。

3. 檔案格式與讀取方式不當

把 Excel 截圖丟給 Agent 做統計，或把純文字轉成掃描 PDF 再讓它解析，都是多繞一圈。做法：文字用 TXT／MD，表格用 CSV／XLSX，程式碼用原始檔，只有在視覺版面重要時才用 PDF 或圖片。這是依任務選擇，不是固定的效率排名。口訣：選對格式，減少不必要的解析。

4. 濫用 Multi-Agent

一篇 800 字的文章，拆給研究、企劃、寫作、校稿、總監五個 Agent，多出來的是交接與協調成本。做法：一個 Agent 能完成就不要分工；任務大、彼此獨立、可以平行時才考慮多 Agent。口訣：Agent 數量不等於生產力。

5. 過度推理、模型大材小用

要替 100 個檔案重新命名，卻請高階模型逐一分析命名方式。做法：規則型任務交給程式或腳本，一般語意任務用輕量模型，複雜推理才動用高能力模型。口訣：讓對的工具做對的事。

6. 重複搜尋與工具呼叫

研究、摘要、做表格的每一輪，都重新搜尋、重新讀同一份文件。做法：重用已取得的資料，建立索引與摘要，必要時用快取，資訊過期再更新。口訣：查過的資料，別無意義地重查。

7. 無差別測試與重新生成

只改了按鈕顏色，卻反覆重建整個網站、跑完全部測試。做法：先局部檢查，再跑相關測試，必要時才整合驗證；高風險的變更仍然要完整測試。口訣：測試要符合風險，不是盲目重跑。

8. 沒有停止條件與用量預算

說「盡可能深入研究」，卻沒限定主題、資料量與完成標準，Agent 會不斷擴大工作。圖上用 while(true) 對照 if(done) break 來比喻。做法：設定任務範圍、來源數量、預算上限與驗收條件，達標就停。口訣：知道何時停止，也是一種效率。

總結：三層工程對應三種節省

層次省在哪
Prompt Engineering（需求清楚）減少猜測與返工
Context Engineering（資料精準）減少無效載入
Harness Engineering（執行可控）減少無效循環

結語：少做不必要的事，才能把 AI 用在真正重要的地方。

留言補充

  • 第 9 點「不記帳」：跑 Agent 要記錄每次的 Token 花費與成果；同一種任務跑三次成本還沒降，就該改成 skill 或模板。
  • 另一招：先叫便宜的模型寫初版，卡關了再升級到高階模型。

跟知識庫怎麼接

  • 這是 Claude 額度整理的同一件事、換成 Agent 的版本。知識庫裡另有三則講 Claude 用量：少讀舊對話、利用快取、把工作分派給不同模型；這篇把「少花」拆成八種具體情境。
  • ①需求模糊就是 AI 使用整理裡的「先定規格」；④濫用多 Agent、⑤大材小用跟 Agent 設計整理的「第一步分工、何時組隊」同一題；⑧沒有停止條件則跟 AI 權限與治理整理的「可停止」同一個原則。
  • 分派給不同模型在知識庫裡有一則實作：用 Sonnet 當主力，在 ~/.claude/agents/ 放兩個子代理檔，CLAUDE.md 寫分工，吃 Token 的雜活派 Haiku、關鍵時刻請 Opus；對話超過 40 萬 Token 就重開、進度存檔。但也有人質疑：專案一大額度未必更耐用，便宜模型常有漏洞，還要貴模型善後，所以「省」要拿成果來算，不是只算 Token。
  • 留言補的第 9 點「記帳」，其實就是上面三層的第四層：量得出來，才知道哪一項該改。

可以怎麼用

先不要八項一起改。挑你最近最常踩的一項：多半是①（需求沒講清楚）或⑧（沒有停止條件）。在下一個任務的第一句話就寫下「完成標準」與「做到哪裡就停」。這期有附一則指令，可以請 Claude Code 先替你做一次八項健檢，再整理成 CLAUDE.md 的規則草稿。

給 Claude Code 的指令

適合情境：想檢查自己平常怎麼用 Claude Code，有沒有在燒 Token，並把省 Token 的習慣寫成固定規則時

請先讀懂下面的需求，列出你打算讀哪些檔案、改哪些地方、步驟是什麼，等我說「好」再動手；不要直接修改或刪除任何檔案。

請幫我做一次「Token 浪費健檢」，並把結果整理成一段可以放進 CLAUDE.md 的『省 Token 規則』草稿。步驟：
1. 先讀我目前專案的 CLAUDE.md（沒有就說沒有），再看我最近的做法，對照下面 8 項，每項用一句白話說「我有沒有踩到」＋一個例子：需求模糊、一次讀太多檔案、檔案格式選錯（文字被轉成圖片或 PDF）、小事也開多個 Agent、規則型工作也用高階模型、同一份資料重複搜尋、小改動也跑全部測試或整個重建、沒有停止條件。
2. 針對有踩到的項目，各寫一條簡短規則，例如：動手前先問清楚受眾、數量、格式與驗收標準；只讀跟任務相關的檔案；改檔名這類規則型工作先寫腳本；查過的資料先摘要存檔再重用；小修改先局部檢查，高風險才跑完整測試；任何『盡可能深入』的任務都要先訂範圍、來源數量與停止條件。
3. 另外加第 9 條『記帳』：同一種任務跑三次成本都沒降，就提醒我改做成 skill 或模板；簡單任務先用便宜模型，卡關再升級。
4. 把規則草稿貼給我看，先不要寫進任何檔案；我說「好」才加到 CLAUDE.md 最後面，並用白話列出你改了什麼。
