Claude Code 快取只活五分鐘：走代理伺服器多花 26% 用量

Claude Code 的使用者常覺得額度怎麼用得這麼快。作者查了自己 8 天的使用紀錄，發現有 26% 的用量花在「把已經讀過的對話整份重新寫進快取」。原因是中間接了代理伺服器。這篇有實測數字，也有一行可以改的設定。

他看到的數字

  • 8 天共 12,545 次請求。
  • 從快取讀出佔 56%、寫進快取佔 35%、AI 真正回覆只佔 9%。
  • 最誇張的一個子任務：等 7～9 分鐘才回來看圖，每次重寫 25～70 萬 token，單項吃掉總量 7.7%。

原因與實測

作者說 Claude Code 的程式寫明：訂閱戶的主視窗快取保留 1 小時，用 API 金鑰則只保留 5 分鐘。他接了 cc-switch（切換 Claude 與 Codex 的代理）後，被當成 API 使用者，只剩 5 分鐘。實測：同一段內容隔 6 分半再送，預設是從快取讀 0、重寫 39,567 token；改成 1 小時後，讀 39,466、重寫 0。

改法

在設定檔加一行，把快取改成 1 小時（圖上寫的是 "CLAUDE_CODE_PROMPT_CACHE_TTL": "1h"）。1 小時快取的寫入貴 1.6 倍，作者模擬後發現主視窗省 9.9%、子代理人反而多花 9.1%，所以只改主視窗，預估省約 10%。另一個更大的問題是自動壓縮要到約 75 萬 token 才啟動，提早到 20～30 萬估計最多再省 30%，他還沒改。

可以怎麼用

如果你也用代理或中轉工具，先看看自己的紀錄，再對照官方文件確認設定名稱，不要直接照抄。

來源與備註：Threads 帳號 @dawson54068，2026-11-08 發文，內容為作者自己的測量；「訂閱戶直連一小時、走代理變五分鐘」的說法沒找到官方說明，各版本行為可能不同。

給 Claude Code 的指令

適合情境：你覺得 Claude Code 額度掉太快、又有接代理或中轉工具時

請先讀懂下面的需求，列出你打算讀哪些檔案、改哪些地方、步驟是什麼，等我說「好」再動手；不要直接修改或刪除任何檔案。

請幫我檢查我的 Claude Code 設定與使用狀況，只讀取、不要修改任何檔案：1. 找出我的 settings.json（使用者層與專案層）並告訴我目前有哪些環境變數設定，特別是跟提示快取（prompt cache）有關的。2. 查官方文件，說明提示快取預設保留多久、怎麼設成 1 小時，以及不同登入方式（訂閱或 API 金鑰、有無代理）有什麼差別。3. 告訴我我現在有沒有接代理，並列出建議的設定；先給我看建議內容，等我同意才動手改。

貼進 Claude Code 後，它會先列出要改什麼、等你說「好」才動手。同一份指令也存在原筆記的「給 AI 的指令」。
