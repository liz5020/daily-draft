約 2 分鐘　頭條　學習與研究　舊文 11/04

研一讀文獻最白費時間的事：三輪讀法

研一剛開始讀論文時，作者每篇都標得五顏六色，卻在想對別人講述時發現：記住很多細節，說不出這篇為什麼值得看。後來他改成分三輪讀，重點不在讀得多細，而在讀完對自己的課題有什麼用。

第一輪：先決定值不值得精讀

拿到英文 PDF，先做成雙語對照，再只看標題、摘要、Figure 和 Discussion，不追求全部看懂，只回答三個問題：它在研究什麼問題？最重要的發現是什麼？它跟我現在的課題有什麼關係？第三題答不上來，就不急著花一小時精讀，因為研究時間經不起每篇從頭看到尾。

第二輪：不摘抄，找證據鏈

以前的筆記是「某蛋白表達升高」「作者採用某模型」「P < 0.05」，每句都對，合起來卻看不出作者怎麼把故事講通。作者改做一張閱讀卡：研究問題 → 做了什麼 → 看到了什麼 → 憑什麼得到這個結論。例如作者說 A 可能影響 B，就追問：先用什麼實驗發現 A 變化？用什麼方法證明 A 與 B 有關？有沒有干預 A？干預後 B 真的跟著變嗎？有沒有其他解釋？這樣讀，方法段不再枯燥，因為是在找「作者拿什麼證據說服我」。

搭配 AI 時，不只問「幫我總結」，而是追問核心假設、哪些實驗直接支持、研究對象與模型、結論的限制、類似問題有哪些設計值得參考。AI 是幫忙拎出論文骨架；具體數據、實驗條件和關鍵結論仍回原文核對，判斷靠不靠譜得自己來。

第三輪：讀完先寫「對我有什麼用」

  1. 我能直接借鑑什麼：實驗模型、指標、分組方式，或 Discussion 裡解釋結果的一個角度。
  2. 我不完全認同什麼：樣本太少？模型能代表真實情況嗎？相關能說明因果嗎？有沒有關鍵環節沒驗證？
  3. 它給我的課題增加了什麼：排除一個方向、想到新問題，或發現自己的實驗少一個對照。

如果讀完只留下幾句摘抄，就回頭問：它究竟改變了我對課題的哪一個判斷？

三個自測問題

  1. 不看原文，能說清作者在解決什麼問題嗎？
  2. 能指出支撐核心結論的關鍵證據與局限嗎？
  3. 能說出這篇對自己課題的一項具體幫助嗎？

答不上來的地方，就是下一輪要補的地方。文獻讀得多不多，和有沒有把它變成自己的研究思考，是兩回事。

可以怎麼用

下一篇論文先只做第一輪：十分鐘內寫下三個問題的答案；第三題寫不出來就先放下。

來源與備註：使用者收藏的社群貼文截圖，作者與平台未註明；是作者個人做法；文中提到的翻譯工具未確認是否含推廣。

給 Claude Code 的指令

適合情境：你想請 AI 幫你拎出一篇論文的骨架、又不想被它的摘要取代思考時

請先讀懂下面的需求，列出你打算讀哪些檔案、改哪些地方、步驟是什麼，等我說「好」再動手；不要直接修改或刪除任何檔案。

我會貼一篇論文（或摘要與重點章節）。請不要只做總結，改用下面順序幫我讀：
1. 先用三句話回答：它研究什麼問題？最重要的發現是什麼？可能跟我的課題（我會在下一則說明）有什麼關係？
2. 做一張證據鏈表：研究問題 → 做了什麼 → 看到了什麼 → 憑什麼得到結論；並列出核心假設、哪些實驗直接支持、研究對象與模型、結論的限制。
3. 列出可能的其他解釋，與作者沒驗證的環節。
4. 凡是具體數據、實驗條件、關鍵結論，請標出原文位置，讓我回去核對；不確定的地方請直接說不確定，不要補。
最後留一欄「我能借鑑什麼／我不認同什麼／對我的課題增加了什麼」給我自己填，你不要先填。

貼進 Claude Code 後，它會先列出要改什麼、等你說「好」才動手。同一份指令也存在原筆記的「給 AI 的指令」。
